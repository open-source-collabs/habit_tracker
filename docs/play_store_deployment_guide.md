# Google Play Store Deployment Guide for Track Free

This guide provides end-to-end instructions for signing, building, and publishing **Track Free** (`co.trackfree.solforge`) to the Google Play Store.

---

## 1. Prerequisites Checklist

- [x] **Target SDK**: Configured to API 35 (Android 15), exceeding Google Play's API 34 minimum.
- [x] **Minimum SDK**: Configured to API 28 (Android 9).
- [x] **R8 / ProGuard Minification**: Enabled with `proguard-rules.pro` optimizing code and shrinking APK/bundle size.
- [x] **Launcher Icon**: leaf-and-check logo. Adaptive icon = gradient background (`drawable/ic_launcher_background.xml`) + artwork foreground and Android 13 monochrome layer (`mipmap-*/ic_launcher_foreground.png`, `ic_launcher_monochrome.png`). Play Store icon: `assets/branding/store/play_store_icon_512.png`. Master artwork: `assets/branding/app_icon_1024.png` (source: `logo_source.png`).
- [x] **Permissions**: `POST_NOTIFICATIONS` (runtime prompt on Android 13+ only), `RECEIVE_BOOT_COMPLETED`, and `INTERNET` (optional cloud sync). No exact-alarm permission: reminders use inexact alarms on Android 12+.
- [x] **Launch screen**: plain white with the centred logo on Android (incl. the Android 12+ splash API) and iOS, generated by `flutter_native_splash` from `assets/branding/splash/`. After changing the `flutter_native_splash:` block in `pubspec.yaml`, run `dart run flutter_native_splash:create`. It hands off to an identical Flutter launch screen (`lib/features/splash/presentation/launch_overlay.dart`) that plays the logo intro and reveals the app once habits are loaded.
- [x] **Security**: Cleartext traffic disabled (`usesCleartextTraffic="false"`) and `allowBackup="false"`.

## 2. Generating Your Upload Keystore

Run the following command in PowerShell / Terminal to create your upload keystore:

### On Windows (PowerShell):
```powershell
keytool -genkey -v -keystore android/app/upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

### On macOS / Linux:
```bash
keytool -genkey -v -keystore android/app/upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

> [!CAUTION]
> **Keep your keystore and passwords safe!** If you lose this keystore or forget your password, you will not be able to publish updates to your app unless you reset the upload key via Google Play Console support.

---

## 3. Configuring `key.properties`

1. Create a file named `key.properties` inside the `android/` directory:
   `android/key.properties`

2. Add your keystore credentials:
   ```properties
   storePassword=YOUR_STORE_PASSWORD
   keyPassword=YOUR_KEY_PASSWORD
   keyAlias=upload
   storeFile=app/upload-keystore.jks
   ```

*(Note: `android/key.properties` and `*.jks` are already added to `.gitignore` so your secrets will never be committed to git).*

## 4. Building the Production App Bundle (.aab)

Google Play Store requires an **Android App Bundle (.aab)** for publishing:

```bash
flutter build appbundle --release
```

The output file will be generated at:
`build/app/outputs/bundle/release/app-release.aab`

> [!IMPORTANT]
> Release builds are signed with the upload key from `key.properties`. If it (or its `storeFile`) is missing, the build **fails** instead of silently signing with the debug key, which Play would reject. For a local-only test build you can opt in with `flutter build apk --release -P allowDebugSigning=true` — never upload such a build.

Pass the store links at build time (each is optional; missing ones are hidden in Settings → About):
```bash
flutter build appbundle \
  --dart-define=PRIVACY_POLICY_URL=https://<you>.github.io/<repo>/privacy_policy.html \
  --dart-define=SUPPORT_EMAIL=<support address> \
  --dart-define=GOOGLE_SERVER_CLIENT_ID=<web OAuth client id>   # Drive sync, see SYNC_SETUP.md
```

**Versioning:** bump `version:` in `pubspec.yaml` for every upload — the part after `+` is the Android `versionCode` and must always increase (e.g. `1.0.0+1` → `1.0.1+2`).

To build an APK for local testing on a physical device:
```bash
flutter build apk --release
```

## 5. Google Play Console Submission Checklist

### A. App Details
- **App Name**: Track Free
- **Short Description**: Minimalist Bento habit tracker with privacy-first offline storage.
- **Full Description**: Track Free is a beautifully designed Bento habit tracker built with privacy in mind. Offline on-device storage, flexible habit schedules, streaks, reminders, custom themes and fonts, home screen widgets, and optional backup to your own Google Drive or iCloud.
- **Category**: Productivity / Lifestyle
- **Privacy policy URL**: host `docs/privacy_policy.html` (e.g. GitHub Pages: Settings → Pages → deploy from `docs/`) and paste its URL here. Fill in the contact line first.

### B. Policy Declarations
1. **Exact Alarms**: Not applicable. The app doesn't request `SCHEDULE_EXACT_ALARM` or `USE_EXACT_ALARM`, so no declaration is needed.
2. **Data Safety** (answers for the questionnaire):
   - **Data collected by the developer**: none. All habit data stays on the device.
   - **Data shared**: none.
   - **Optional Google Drive sync**: the app signs in with Google (account email is shown in the app) and writes the user's own data to their Drive app-data folder. This is user-initiated transfer to the user's own account; declare "User IDs / Email address — not collected" only if your reading of Play's definition agrees, otherwise declare *Email address* as processed on-device for *App functionality*, not shared.
   - **Encryption in transit**: yes (HTTPS to Google APIs).
   - **Deletion**: users can delete all data in Settings → Delete all data.
   - The app is **not** end-to-end encrypted — don't claim "encrypted backup" in the listing.
3. **Target Audience**: 13 and older.

### C. Release Tracks
1. Upload `app-release.aab` to **Internal Testing**.
2. Add your email as an internal tester to test installation directly from Google Play.
3. Promote to **Closed Testing** or **Production** once validated.
